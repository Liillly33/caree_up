# 프로젝트 수행 내용 기반 SBERT 추천 반영

기존 서버를 종료하고 이 ZIP의 `start_local.py`를 실행한 뒤 새로 추천받아주세요. **DB 열·SQL 추가 실행은 필요 없습니다.** 마이페이지/설문/프로젝트 완료가 저장하는 `SPEC_PROJECT_EXPERIENCE`를 그대로 사용합니다. 과거 추천 기록의 점수는 덮어쓰지 않습니다.

## 계산 역할

- 핵심·보조 기술 충족도와 BM25는 보유 기술스택·자격증 입력에서만 기술명을 추출합니다. 프로젝트 문장의 기술명을 여기에 합치지 않습니다.
- SBERT 모델은 기존 `jhgan/ko-sroberta-multitask`를 유지합니다. 프로젝트에서 수행한 작업과 공고의 주요업무·자격요건·우대사항 문장을 각각 벡터로 변환하고 코사인 유사도를 계산합니다. 기존의 '겹치는 기술명 목록끼리 SBERT로 비교'하는 경로를 제거했습니다.
- 기본 비중은 핵심 50 / 보조 10 / BM25 10 / 프로젝트 SBERT 30입니다. 기존 중립 그룹 정규화와 기술점수 92점, 선호직무·기업규모 가점은 유지합니다.

## 프로젝트와 공고 문장 처리

프로젝트는 줄바꿈·문장부호·일부 연결 표현을 기준으로 작업 단위로 나눕니다. 동일한 문장을 반복하면 한 번만 사용하고, 임베딩 코사인 유사도 0.98 이상인 매우 유사한 문장도 중복 후보로 처리합니다. 수행 문맥이 없는 단순 기술명 나열, NONTECH, 명시적인 미경험·예정 문장은 프로젝트 비교 근거로 사용하지 않습니다.

공고도 주요업무·자격요건·우대사항을 문장 단위로 분리하고 기존 TECH/NONTECH 예시 분류를 적용합니다. REVIEW 중 구체적인 기술 작업 문맥이 있는 경우만 보수적인 규칙으로 포함합니다. 협업 태도·학력 등의 비기술 문장은 제외합니다. 사람의 공고별 기술 제외 판정과 Git/GitHub 기본 도구 제외도 유지합니다.

공고 문장마다 가장 가까운 프로젝트 작업 문장 **하나**의 코사인 유사도를 사용합니다. 각 구역 안에서는 문장별 점수의 평균을 구하고, 주요업무:자격요건:우대사항 **2:2:1 가중 평균**으로 합칩니다. 없는 구역은 평균의 분모에서 제외합니다. 공고에 반복되거나 여러 구역에 중복 등장한 같은 문장은 한 번만 반영합니다.

프로젝트 개수·글자 수·문장 수 자체에 가산점은 없습니다. 서로 다른 관련 작업을 추가해 공고의 다른 업무까지 설명하면 관련성이 개선될 수 있지만, 같은 경험을 복제하거나 무관한 문장을 추가한 횟수로 점수를 더하지 않습니다.

## 미입력과 기술 보유의 구분

프로젝트 미입력은 `NOT_PROVIDED`, 비교할 수행 문장이 없으면 `NO_SCORABLE_PROJECT_TASKS`, 비교가 꺼져 있으면 `SEMANTIC_DISABLED`로 구분합니다. 이를 경험 없음이나 0점 정답으로 취급하지 않습니다. 프로젝트를 비교할 수 없으면 SBERT를 제외하고 기존 비중 50:10:10을 합계 100%로 비례 정규화합니다. 공고에 비교할 기술 문장이 없는 경우에도 해당 공고의 기술 기반 점수로 계산합니다.

문장이 비슷하다는 이유로 Docker·Kubernetes 등의 기술 보유를 추정하지 않습니다. 기술 목록이 전혀 겹치지 않아도 프로젝트 관련성이 있으면 SBERT 부분만 받을 수 있습니다. 이때도 기술 충족도·BM25는 해당 기술을 보유한 것으로 계산하지 않습니다. 기술스택이 비어 있고 프로젝트만 입력한 경우도 관련 공고를 비교할 수 있으나, 확인되지 않은 기술 점수를 자동으로 채워주지는 않습니다.

## 점수 기준과 검증 한계

코사인 유사도를 그대로 '적합도 퍼센트'로 부르지 않습니다. 초기 변환 기준은 0.40 이하 0, 0.85 이상 1, 그 사이 선형 변환입니다. `data/scoring_policy.json`의 `project_semantic`에서 구역별 비중·중복 기준·변환 기준을 조정할 수 있습니다. 이 값은 사람의 추천 적합도 평가로 최적화한 수치가 아닙니다.

## 적용 범위

## 계산 방식과 예외

핵심·보조·중립 그룹별 IDF 가중 충족률을 계산하고, 일치 근거가 직무별 공고 기술 수 중앙값에 비해 적으면 충족도 점수를 낮춥니다. 전체 사용자 기술 수를 분모로 사용하지 않습니다. 사용자에게 무관한 기술이 추가됐다는 이유로 기존 공고 점수가 떨어지지 않습니다.

기본 기술충족 배점은 합계 60%입니다. 핵심·보조가 모두 있고 중립이 없으면 50:10 그대로입니다. 중립이 있으면 중요도 기준값 핵심 0.5·보조 0.1·중립 0.3을 사용해 실제 존재하는 그룹 안에서 합계 60%로 정규화합니다. 빈 그룹에는 공짜 점수를 주지 않으며, 없는 핵심/보조 그룹은 추정해서 만들어내지 않습니다. 하나의 그룹만 존재하면 그 그룹이 기술충족 배점을 맡되, 일치 근거 부족 보정은 유지합니다. 결과 `importance.groups.*.effective_weight`에서 공고별 실제 비중을 확인할 수 있습니다.

BM25는 기존 전체 공고 코퍼스와 직무별 고정 기준으로 계산합니다. SBERT는 기존 기술명 목록 비교 입력과 일치 여부 게이트를 유지하고, 기술 충족률의 크기를 다시 곱하지 않습니다. 자격요건과 우대사항의 BM25·SBERT는 기존 2:1 구분 가중치로 합칩니다. 핵심/보조 충족도는 공고 전체의 기술을 한 번씩만 계산합니다.

사람이 검토한 기술이 주요업무에만 존재하더라도 요구 근거로 사용할 수 있도록 보완했습니다. 원문 출처는 `JOB_RESPONSIBILITIES`로 명확히 남깁니다. 기존 TECH/NONTECH 분류가 놓쳤어도 해당 기술의 사람 핵심/보조 판정이 있다면 이를 우선합니다. 전역 점수 제외 항목은 계속 제외합니다.

비교용 exact 모드는 기술충족도 100%, bm25/lexical-only 모드는 SBERT 비중을 기술충족도 쪽으로 재배분합니다. 실제 서비스의 hybrid 모드는 위 기본 배점을 사용하며 SBERT가 없으면 조용히 다른 모델로 대체하지 않습니다.

- 중기목표일에는 해당 목표가 메인퀘스트가 되고 중간보스가 등장합니다. 완료 비밀번호는 해당 목표일의 월일 네 자리(MMDD)이며 완료 창에서 확인할 수 있습니다. 이것은 재시작에 필요한 **로그인 비밀번호와 다릅니다**.
- 중간보스와 최종보스는 각각 한 번 +40 레벨을 지급합니다. 40·80레벨에서 전직합니다. 프로젝트는 마법사 ROUTE 캐릭터를 사용합니다.
- 최종일 이후 최종보스를 토벌하면 프로젝트 완료 기록(메인 기술이 포함된 프로젝트 제목)을 기술 스택에 저장하고 매칭 리포트를 다시 계산합니다. 사용자가 완료를 확인한 결과이며 모든 기술 태그를 임의로 보유 기술로 추가하지 않습니다. 테스트 모드 완료도 실제 스펙에 반영합니다.

### DB·인증

## AI 프로젝트 추천

기존 서버를 종료하고 **이 압축 파일 안의 `start_local.py`**를 실행합니다. 현재 Supabase에는 `sql/006_project_curriculum.sql`을 적용했습니다. 기존 SQL을 다시 실행할 필요는 없습니다.

- 새 로드맵 생성 시 자격증과 프로젝트를 각각 하나씩 자동 추천합니다. 기존 로드맵은 처음 열 때 프로젝트를 자동 추천합니다.
- 마법사 ROUTE 프로젝트 카드에 프로젝트명·추천 이유·예상 기간이 표시됩니다.
- 카드를 누르면 중기목표와 각 단계의 고정 일일목표가 펼쳐집니다. **이 프로젝트로 모험 시작**을 누르면 해당 로드맵의 `PJT_ID`에 저장하고 모험을 시작합니다.
- 카드 아래 **🔄️다른 프로젝트 추천받기**는 현재 추천을 제외한 관련 후보에서 다시 고릅니다. 후보가 없으면 기존 추천을 유지합니다.
- 추천은 `PJT_RECOMMENDATIONS`, 실제 선택은 `PJT_ID`로 구분합니다. 재추천은 기존 선택을 바꾸지 않습니다. 새로고침 후에도 저장 결과를 불러옵니다.
- AI 오류가 나도 로드맵과 기존 추천·선택은 유지합니다. 카드 아래 재추천으로 다시 시도할 수 있습니다.

### 추천 방식

프로젝트의 홈 어드벤처·몬스터·일일퀘스트·EXP가 연결되어 있습니다. 자격증 모험과 테스트 달력도 함께 지원합니다.

### DB 변경

새 테이블 없이 SC_CAREER_ROADMAP에 `PJT_RECOMMENDATIONS JSONB` 하나를 추가합니다. 기존 `PJT_ID` FK를 실제 선택 저장에 사용합니다. 새 저장·선택 함수는 본인의 최신 로드맵만 변경하며, 일반 사용자의 테이블 직접 UPDATE 권한은 추가하지 않았습니다. 기존 자격증·어드벤처 함수는 수정하지 않았습니다.

## 회차 선택과 데모 날짜

회차의 선택 가능 여부는 커리업 어드벤처가 사용하는 날짜를 기준으로 계산합니다. 테스트 모드이면 적용한 테스트 날짜, 실제 모드이면 한국 시간 기준 오늘입니다.

예: 일정 드로어에서 **2026-02-01을 테스트 날짜로 적용**하면 SQLD 제60회(3월 7일)부터 선택할 수 있습니다. 3월 7일 당일도 선택 가능하며, 3월 8일부터는 해당 회차를 지난 시험으로 표시합니다. **실제 오늘로 돌아가기**를 누르면 실제 날짜 기준으로 복귀합니다.

테스트 중 다른 회차로 모험을 시작하면 기존 모험 시작 API와 테스트 날짜 적용 API를 순서대로 호출하여 테스트 날짜·시간을 유지합니다. 날짜 복원이 실패하면 진행 버튼을 잠그고 재적용 버튼을 표시해 실제 진행을 잘못 기록하지 않도록 합니다.

회차 선택의 날짜 처리와 기존 자격증 추천·점수 계산은 유지됩니다.

## 이번 버전 사용법

1. 공고를 선택해 커리어 로드맵을 생성하면, 보완점에 가장 적합한 자격증 **하나**를 자동으로 추천합니다. 별도의 추천받기 버튼을 먼저 누를 필요가 없습니다.
2. 셀프 커리큘럼 자격증 카드에 자격증 이름과 추천 이유가 바로 표시됩니다.
3. 자격증 카드를 누르면 회차 선택이 펼쳐집니다. 회차를 고른 뒤 **이 회차로 모험 시작**을 누릅니다.
4. 다른 후보를 보고 싶으면 자격증 카드 아래 작은 **🔄️다른 자격증 추천받기** 버튼을 누릅니다. 현재 자격증을 제외한 관련 후보에서 다시 선택합니다.
5. 적합한 다른 후보가 없으면 현재 추천을 유지하고 짧게 안내합니다. 관련 없는 자격증을 억지로 추천하지 않습니다.

자동 추천은 로드맵에 저장됩니다. 다시 열어도 같은 근거의 추천을 새로 만들지 않습니다. 기존 로드맵에도 처음 열 때 자동으로 단일 추천을 적용합니다. 추천을 바꾸어도 이미 진행 중인 모험은 자동으로 바뀌지 않습니다. 새 회차로 모험을 시작해야 목표가 변경됩니다.

AI 오류가 발생해도 로드맵 자체는 생성됩니다. 자격증 카드에 오류를 표시하고 작은 재추천 버튼으로 다시 시도할 수 있습니다.

기존 서버를 종료하고 이 ZIP의 start_local.py로 다시 실행합니다.

## 추천 기준과 AI 역할

서버가 화면에 표시하는 보완점과 자격증 기술 태그를 먼저 대조합니다. 직접 연결되는 후보만 Gemini에 전달하고, Gemini가 가장 적합한 자격증 하나와 추천 이유를 작성합니다. 목표 공고의 기술 요구 근거와 사용자 기술·보유 자격증을 참고하되 이름·이메일·나이는 전달하지 않습니다. 보유한 자격증은 제외합니다.

모델이 없는 자격증, 중복 자격증, 관련 없는 보완점 번호를 반환하면 저장하지 않습니다. 자격증으로 실무 프로젝트·배포 경험이 충족된다고 처리하지 않습니다. 후보가 없으면 자격증을 강제로 만들지 않고 프로젝트 학습 방향을 안내합니다. 실제 프로젝트/공모전 생성 기능은 이전과 같이 준비 중입니다.

현재 자격증 기술 태그와 학습 범위는 프로젝트용으로 작성한 매핑입니다. 검토 후 SC_LC에서 변경할 수 있으며 별도 모델 파인튜닝은 필요하지 않습니다. TECH/NONTECH 라벨이나 채용공고 추천 점수·순서는 이번 작업에서 변경하지 않았습니다.

## 회차·차수와 모험

같은 자격증의 여러 회차는 한 추천 안의 선택 목록으로 묶습니다. 등록된 시험일이 지난 회차는 표시하되 새 모험 시작 선택은 막습니다. 2차 시험은 1차 합격 등 응시조건을 사용자가 확인해야 합니다. 응시자격을 자동 판정하거나 원서접수 여부를 확인하는 기능은 없습니다.

리눅스마스터 1차 완료는 1차 합격만 기록하며 보유 자격증에 최종 자격을 추가하지 않습니다. 2차 또는 최종 시험을 완료해야 보유 자격증에 정식 이름을 추가합니다. 보유 자격증에는 연도·회차를 붙이지 않습니다. SQL 개발자는 기존 점수 계산 사전과 연결되도록 SQLD, 데이터분석 준전문가는 ADsP로 저장합니다. 취득만으로 기술이나 실무 경험을 자동 추가하지 않습니다.

- 메인 70 EXP, 일일목표 각각 30 EXP, 100 EXP마다 레벨업. 레벨/하루 횟수 제한 없음.
- 중기·최종목표 최초 완료 각각 +40 레벨. 누락 보상 보정·중복 지급 방지 유지.
- 1차 전직 Lv.40, 2차 전직 Lv.80. 낮/밤·걷기·공격·타격 연출 유지.
- 자격증을 바꿔도 플레이어 레벨·EXP·사용자 목표를 유지합니다. 시험별 토벌·보상·사용자 수정 일정은 STATE.tracks에 보관하며 되돌아와도 중복 보상을 주지 않습니다.
- 날짜 테스트는 실제 상태와 분리됩니다. 테스트 합격은 실제 자격증을 변경하지 않습니다.
- 완료 비밀번호는 시험일 MMDD입니다. 기존 정보처리기사 기본 레코드는 필기 0130/실기 0418을 유지합니다.
